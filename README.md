# Mood n Food

เว็บแอพช่วยเลือกเมนูอาหารไทยตามมู๊ด ณ ตอนนั้น สำหรับคนที่หิวแต่คิดไม่ออกว่าจะกินอะไร ตอบคำถาม 3 ข้อ (มู๊ด → รส → ความเผ็ด) แล้วได้เมนูหลัก 1 จาน พร้อมเหตุผลว่าทำไมเหมาะ และเมนูสำรองอีก 2 จาน ใช้เวลาไม่ถึงนาที

หน้าตาของแอพออกแบบเป็นคูปองศูนย์อาหาร ตอบแต่ละข้อจะมีตรายางประทับแล้วคูปองถูกฉีกออก ผลลัพธ์ออกมาเป็นบัตรคิว

## ฟีเจอร์

- **มู๊ด 4 แบบ ผูกกับประเภทอาหาร:** เครียด (รสจัด/เคี้ยวสนุก), เหนื่อยล้า (ซุปอุ่น/ย่อยง่าย), อยากฮีลใจ (กรอบ/ชีส/ของหวาน) และเบื่อ (แปลกใหม่/ปิ้งย่างกินด้วยกัน)
- **เมนูไทย 158 จาน:** แต่ละจานติด tag รส ลักษณะอาหาร ความเผ็ด และส่วนผสม
- **ข้อจำกัดอาหาร:** ฮาลาล, วีแกน และแพ้อาหาร (กุ้ง/ปู/หอย, ปลา, ถั่วลิสง, ไข่, นม) เป็นเงื่อนไขเด็ดขาด ไม่มีการผ่อนปรน
- **ไม่แนะนำซ้ำ:** จำเมนูที่เพิ่งแสดงและเมนูที่กด "ไม่เอา" ไว้ในเครื่อง
- **ขี้เกียจตอบ สุ่มให้เลย:** ข้ามคำถามทั้งหมด
- **หลังได้เมนู:** มีปุ่ม "หาร้านแถวนี้" (เปิด Google Maps) และปุ่ม "ชวนเพื่อนไปกิน" (ใช้ Web Share API ถ้าเบราว์เซอร์ไม่รองรับจะคัดลอกข้อความแทน)
- **ไม่มี backend ไม่ต้องสมัคร:** ข้อมูลทั้งหมดอยู่ใน localStorage ของเครื่องผู้ใช้

## เริ่มใช้งาน

ต้องมี Node.js 20 ขึ้นไป (ทดสอบกับ Node 24)

```bash
npm install
npm run dev      # เปิด dev server ที่ http://localhost:5173
```

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | dev server พร้อม hot reload |
| `npm test` | รัน unit test (Vitest) |
| `npm run lint` | ตรวจโค้ดด้วย oxlint |
| `npm run build` | type check แล้ว build ไฟล์ static ไว้ที่ `dist/` |
| `npm run preview` | เปิดดู build จริงที่ http://localhost:4173 |

`dist/` เป็นไฟล์ static ล้วน นำไปวางบน Vercel, Netlify หรือ static host ใดก็ได้

## โครงสร้าง

```
src/
├─ data/
│  ├─ menus.ts        # ฐานข้อมูลเมนูทั้งหมด
│  └─ questions.ts    # คำถาม ตัวเลือก และตัวเลือกข้อจำกัดอาหาร

│  ├─ types.ts        # type ของเมนู คำตอบ ข้อจำกัด ประวัติ
│  └─ recommend.ts    # ให้คะแนนและจัดอันดับเมนู (pure function)
├─ lib/
│  ├─ storage.ts      # อ่าน/เขียน localStorage แบบกันพัง
│  └─ share.ts        # แชร์ผล / คัดลอกข้อความ
├─ components/        # Coupon, Perf (รอยปรุ), Stamp, ไอคอน SVG
├─ pages/             # Quiz, Prefs (ข้อจำกัดอาหาร), Result

└─ index.css          # สไตล์ทั้งหมด (CSS ธรรมดา + custom properties)
tests/                # เทสต์ของเอนจิน ข้อมูลเมนู และ storage
```

## เอนจินแนะนำเมนูทำงานยังไง

`recommend(menus, answers, prefs, history, rng)` ใน `src/engine/recommend.ts`

1. ตัดเมนูที่ขัดกับข้อจำกัดอาหารออกก่อน ขั้นนี้ไม่มีการผ่อน
2. ตัดเมนูที่เพิ่งแสดงและที่ถูกปฏิเสธออก ถ้าเหลือไม่ถึง 3 จาน จะยอมให้เมนูที่เพิ่งแสดงกลับมาก่อน แล้วค่อยยอมเมนูที่ถูกปฏิเสธ
3. ให้คะแนน:
   - มู๊ดให้คะแนนตามลักษณะอาหาร (`traits`) ของเมนู
   - รสที่ตรงได้ +3
   - ความเผ็ดตรงได้ +2 และหัก 2 ต่อทุกระดับที่ห่างออกไป
4. บวกค่าสุ่มเล็กน้อยเพื่อไม่ให้ผลซ้ำทุกครั้ง แล้วเลือก 3 อันดับแรก
5. เหตุผลแต่ละข้อมาจากปัจจัยที่ได้คะแนนสูงสุด 2 อย่าง

ค่าน้ำหนักทั้งหมดอยู่ใน `WEIGHTS` ที่เดียว ปรับจูนได้โดยไม่ต้องแตะส่วนอื่น

## เพิ่มหรือแก้เมนู

เพิ่มเมนูใหม่ใน `src/data/menus.ts` ใต้หมวดที่ตรงกัน ตัวอย่าง:

```ts
{ id: 'khao-man-gai', name: 'ข้าวมันไก่', emoji: '🍗', category: 'rice',
  taste: ['mild', 'salty-rich'], traits: ['gentle'], spice: 0,
  contains: ['poultry'], blurb: 'ข้าวมันหอม ไก่นุ่ม พร้อมซุปใสอุ่นๆ' },
```

- `traits`: ต้องมีอย่างน้อย 1 ค่า เมนูจะเข้ากับมู๊ดไหนขึ้นอยู่กับค่าในนี้ (`bold`, `chewy`, `soupy`, `gentle`, `crispy`, `cheesy`, `sweet`, `novel`, `diy`)
- `contains`: ติดแบบระวังไว้ก่อน ถ้าสูตรทั่วไปมักใส่ให้ติดไว้เสมอ
  - น้ำปลาและปลาร้านับเป็น `fish`
  - ซอสหอยนางรม กะปิ กุ้งแห้ง และหมึก นับเป็น `shellfish`
  - ข้อมูลนี้ใช้กรองเมนูให้คนที่แพ้อาหาร ห้ามละไว้
- `spice`: 0–3 และ `taste` เลือกได้หลายค่า

หลังแก้ ให้รัน `npm test` ทุกครั้ง เทสต์จะตรวจว่า id และชื่อไม่ซ้ำ ทุกเมนูมี trait ทุกมู๊ดมีเมนูพอทั้งสำหรับวีแกนและฮาลาล และข้อจำกัดอาหารทุกชุดยังเหลือเมนูให้เลือก

## เอกสารอื่น

## ข้อควรรู้

ข้อมูลส่วนผสมมาจากสูตรทั่วไป แต่ละร้านอาจทำต่างกัน แอพจึงแสดงข้อความเตือนให้ผู้ใช้สอบถามร้านอีกครั้งทุกครั้งที่เปิดข้อจำกัดอาหารไว้ ตัวเลือกฮาลาลกรองได้แค่เมนูที่มีหมู ยังไม่ได้ตรวจว่าร้านได้รับการรับรองฮาลาลหรือไม่
